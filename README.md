## 1 项目背景与目标

### 1.1 项目背景

随着大语言模型（LLM）在组织内部的快速落地，业务团队同时引入了开源模型、自研模型与多个外部商用 API，模型数量快速增长、能力差异显著、版本迭代频繁。然而，当前评测工作高度依赖人工脚本与零散的公开榜单，存在标准不统一、过程不可复现、结果难比较、成本不可控等突出问题，难以支撑组织级、多维度的模型选型与持续验收。

业界主流评测体系已构建了覆盖客观题、主观题、对齐与安全的综合评测能力，并通过任务编排与自动化流水线提升评测效率。组织亟需一套面向内部场景、可标准化与自动化运行的评测基础设施，以建立统一的模型评估标尺。

### 1.2 建设目标

- **标准化**：统一评测数据集、指标定义、评判协议与报告格式。
- **自动化**：从数据加载、模型推理、自动评判到结果聚合与报告生成全流程无人值守。
- **可复现**：数据集版本、模型版本、推理引擎与超参全程留痕，结果可追溯、可重算。
- **可比较**：支持模型之间、版本之间、不同推理后端之间的横向与纵向对比。
- **可扩展**：分层解耦，模型、数据集、评测算子、推理引擎均可插件化替换。
- **组织级**：多租户、权限审计、资源配额、GPU 调度与安全合规。

### 1.3 适用范围

本平台面向组织内部 AI 中台、算法研发、业务选型与安全合规团队，支撑模型选型、版本验收、上线前的对齐与安全评估，以及线上模型的持续回归与监控。

## 2 竞品分析：OpenCompass 司南

OpenCompass 司南是新型的大模型开源评测体系，其核心能力体现在统一的任务配置、丰富的数据集与评测算子、自动化运行流水线以及可视化的榜单对比。本平台以司南为对标基准，结合组织内部场景进行裁剪与增强。

### 2.1 对标能力矩阵

| 能力域 | OpenCompass 司南 | 本平台对标策略 |
| --- | --- | --- |
| 评测任务编排 | 配置化任务、DAG 调度 | 对齐司南 + 组织级任务队列与优先级 |
| 数据集体系 | MMLU / C-Eval / GSM8K 等公开集 | 引入公开集 + 自建业务数据集仓 |
| 评测算子 | 客观题、主观题、LLM-as-Judge | 对齐算子库 + 扩展业务评判算子 |
| 推理后端 | 多种推理接口适配 | 统一推理抽象 + vLLM/TGI/TRT-LLM |
| 结果与报告 | 榜单对比、结果可视化 | 自动报告 + 多维对比看板 |
| 复现性 | 版本化数据与配置 | 数据/模型/引擎/超参全程版本化 |
| 分布式运行 | 任务分片与并行 | Kubernetes 调度 + GPU 弹性池 |

*表 1 与 OpenCompass 司南的对标能力矩阵*

### 2.2 差异化增强

- **组织数据集仓**：构建内部业务评测数据集，支持脱敏入库与数据血缘管理。
- **多租户与配额**：按项目空间隔离，GPU/并发配额可控，支持部门级核算。
- **安全合规评测**：内置对齐、安全、价值观与合规专项评测包。
- **持续回归**：模型上线后定期回归评测，对接监控告警。

## 3 平台总体架构

平台采用六层架构，自上而下分别为用户接入层、应用服务层、评测引擎层、数据与知识层、模型推理层和基础设施层。各层之间通过明确契约解耦，支持独立演进与替换。整体遵循"接入多样性、引擎标准化、数据资产化、推理弹性化、基础设施云原生化"的设计原则。

### 3.1 设计原则

- **分层解耦**：层间通过标准接口与数据契约通信，避免垂直耦合。
- **能力插件化**：数据集、算子、推理后端、报告模板均以插件方式注册。
- **云原生**：基于 Kubernetes 构建，全部服务容器化、声明式部署。
- **安全优先**：多租户隔离、最小权限、全链路审计。

### 3.2 核心价值流

平台围绕评测任务的全生命周期组织核心价值流：从数据准备到报告输出的端到端自动化流水线。

## 5 分层能力说明

### L1 用户接入层

- 提供 Web 控制台、CLI/SDK、REST API 与 IDE 插件四种接入方式，适配算法、业务与运维角色。
- 内置多租户门户与 SSO，集成 OAuth2/SAML/LDAP，统一鉴权与项目空间隔离。
- 支持邮件、IM、Webhook 等多种评测完成通知方式。

### L2 应用服务层

- 任务编排服务负责评测 DAG 的定义、依赖管理与失败重试，支持批量评测与并发控制。
- 模型注册中心管理模型元数据与版本，对接内部/外部模型仓库与权重存储。
- 报告与看板服务自动生成报告、提供多维对比分析，并支持导出 PDF/Excel。
- 模型评分图谱：以综合评分 × 推理成本散点呈现全部已评测模型，标注性价比前沿，支撑模型选型与版本对比。
- 权限与审计模块提供 RBAC、操作审计与数据血缘，满足合规要求。

### L3 评测引擎层

- OpenCompass 引擎作为核心运行时，对齐司南的任务模型与配置规范。
- 评测能力集覆盖客观题、主观题、对齐与安全四大域，支持扩展自定义算子。
- 评测算子库内置 Bleu、Rouge、Pass@k、LLM-as-Judge 等，支持加权聚合与置信区间。
- 推理后端适配层屏蔽 vLLM/TGI/TRT-LLM 差异，对评测任务透明。
- 自动化流水线串联数据加载→推理→评判→聚合，支持断点续跑。

### L4 数据与知识层

- 评测数据集仓统一管理 MMLU、C-Eval、GSM8K 等公开集与自建业务集。
- 数据集版本管理提供快照、Diff 与复现性保障。
- 答案与标注库管理标准答案、人工标注与偏好数据。
- 评测结果存储结构化指标与全量推理日志，便于二次分析。
- 向量与知识库支撑 RAG 评测语料与检索质量评估。

### L5 模型推理层

- GPU 推理集群基于 A100/H800，支持弹性扩缩容与多优先级调度。
- 多引擎推理支持 vLLM、TensorRT-LLM、TGI，按模型与场景择优。
- 量化与加速覆盖 FP8/INT4、KV-Cache 优化、Prefix Caching。
- 模型权重管理通过分布式存储与预加载缓存降低冷启动。
- 多模态推理运行时支撑图文、语音模型评测。

### L6 基础设施层

- Kubernetes 底座提供容器编排、节点池与 GPU 调度能力。
- 对象存储（S3/MinIO）承载数据集、模型权重与评测产物。
- 消息与队列（Kafka/RabbitMQ）作为事件总线串联异步任务。
- 可观测平台（Prometheus/Grafana/Loki）实现指标、面板与日志统一。
- 安全合规基座提供网络隔离、密钥管理与全链路审计。

## 6 评测流程与自动化

评测任务以配置即代码方式定义，全流程自动化，支持单模型评测、多模型对比、版本回归与持续监控四种典型场景。任务执行遵循统一的状态机，保证可观测与可重算。

### 6.1 任务状态机

| 状态 | 说明 | 触发动作 |
| --- | --- | --- |
| Draft | 任务定义草稿 | 保存配置 / 校验数据集与模型 |
| Pending | 已提交待调度 | 进入优先级队列 |
| Running | 推理 + 评判进行中 | 分片并行 / 实时日志 |
| Paused | 暂停（可断点续跑） | 保存中间结果 |
| Done | 评测完成 | 聚合指标 / 生成报告 |
| Failed | 失败 | 失败定位 / 重试 / 告警 |

*表 2 评测任务状态机*

### 6.2 自动化关键点

- **自动评判**：客观题自动评分，主观题由 LLM-as-Judge + 抽样人工复核。
- **自动聚合**：按数据集、能力域、难度、语言多维聚合，输出加权总分。
- **自动报告**：模板化生成 PDF/HTML 报告，含对比图与异常项标注。
- **自动回归**：模型上线后按计划触发回归任务，对比历史基线告警。
- **断点续跑**：推理结果落盘，失败分片可单独重算，避免全量重跑。

## 9 模型评分图谱

模型评分图谱（Model Score Graph）是平台结果分析的核心可视化能力：以"综合评分 × 推理成本"为核心坐标，将平台内全部已评测模型绘制为可交互的二维散点图谱，并叠加性价比前沿（Pareto Frontier），为模型选型、版本验收与成本决策提供统一视图。

### 9.1 图谱价值

- **模型选型**：同屏对比自研、开源与商用 API 模型，快速定位"高评分 · 低成本"甜点区模型。
- **性价比决策**：以每任务推理成本（USD，对数刻度）为横轴、综合评分为纵轴，量化单位成本的能力收益。
- **版本演进追踪**：同一模型多个版本（low / medium / high / max）连点成线，直观呈现迭代收益与成本变化。
- **基线沉淀**：从图谱中一键将优选模型加入对比清单，生成对比报告并沉淀为生产基线。

### 9.2 图谱样例

下图给出模型评分图谱样例（数据源自 Artificial Analysis Intelligence Index v4.1，覆盖 128 个主流模型）。横轴为每任务推理成本（美元，对数刻度），纵轴为智能指数综合评分，颜色区分厂商；左上方"低成本 · 高评分"区域即为性价比甜点区。

![image_3.jpeg](img/image_3.jpeg)

*图 3 模型评分图谱样例（综合评分 × 推理成本，来源：Artificial Analysis）*

- **坐标读法**：横轴成本按对数刻度展开，纵轴为加权综合评分，气泡越靠左上性价比越高。
- **前沿识别**：灰色虚线为性价比前沿，位于前沿上的模型代表当前成本档位的最优选择。
- **厂商对比**：颜色区分厂商与系列，可快速识别各厂商在不同成本档位的布局密度。
- **异常发现**：远离主体分布的离群点需重点复核，可能是评测异常或新晋高性价比模型。

### 9.4 平台实现要点

- **数据来源**：评分取自指标计算引擎的加权聚合结果，成本由 token 单价与任务实测消耗计算，时延与吞吐取自全量推理日志。

| Y 轴（纵轴） | 综合评分（能力域加权聚合） | 单一能力域得分 / 安全专项分 |
| 气泡颜色 | 厂商 / 模型系列 | 推理后端 / 接入方式（自研·开源·商用API） |
| 气泡大小 | 固定 | 日均调用量 / 评测频次 |
| 连 线 | 同系列版本演进连线 | 性价比前沿（Pareto Frontier）开关 |

*表 5 模型评分图谱默认维度配置*

- **血缘可追溯**：每个气泡绑定数据集快照、模型版本、推理引擎与超参指纹，点击可回溯原始评测任务。
- **前端渲染**：基于 ECharts / AntV 实现大规模气泡的流畅渲染与缩放，图谱快照可存档复现。
- **权限隔离**：按项目空间过滤可见模型，商用 API 成本按租户隔离展示。

## 10 安全、合规与可观测性

### 10.1 安全与合规

- **多租户隔离**：项目空间级别数据与资源隔离，越权访问拒绝并审计。
- **最小权限**：RBAC 细粒度授权，按角色、项目、操作三维度控制。
- **数据脱敏**：业务评测数据入库前自动脱敏，敏感项不落盘原文。
- **密钥管理**：模型 API Key、推理凭证统一由 Vault 托管，按需注入。
- **全链路审计**：任务、数据、模型、结果操作全量留痕，可追溯回放。
- **合规评测**：内置价值观、合规、隐私专项评测，作为上线准入门禁。

### 10.2 可观测性

- **运行监控**：Prometheus 采集 GPU 利用率、推理吞吐、任务时延等核心指标。
- **可视化面板**：Grafana 提供集群、任务、模型三个维度的实时面板。
- **日志检索**：Loki/ELK 汇聚全链路日志，支持按任务、模型、时间检索。
- **告警**：任务失败、资源耗尽、指标劣化自动告警并触发回归任务。
- **产物可追溯**：每次评测产物包含数据版本、模型版本、引擎版本与超参指纹。
